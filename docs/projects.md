# 项目模式设计

> 说明：本文最初按多用户设计，2026-11-12 已整体改为单人语义。文中提到的「共享」只指会话或资源的可见性开关，不涉及其他登录用户。

项目是一种专家。它自己完成任务，需要时把别的专家当作工具调用。任务是这个项目下的对话。本机使用者可以看到全部任务，并可以继续问。

本文是设计，尚未实现。专家上的「共享会话」已经单独落地：会话默认私有，可以把某一条开放出去。那不是项目。

## 区别和联系

专家、团队、项目都是 `agents` 里的一行。工作区、记忆、对话都挂在这一行上。差别在谁干活、资源归谁、上下文怎么带。

| | 专家 `kind=expert` | 团队 `kind=team` | 项目 `kind=project` |
|---|---|---|---|
| 是什么 | 一个人可用的专家 | 主持人加至少两名成员 | 一块共享的工作，本身也是专家 |
| 谁干活 | 自己 | 主持人只调度，成员干活 | 自己做完；需要时再调用专家 |
| 工具 | 干活的全套，含技能 | 只有 `agent_list`、异步 `ask_agent`、记忆、时间 | 和专家同一套 |
| 调用专家 | 可以同步调用 | 异步派工，编制写在 `.octop/manifest.json` | 同步调用，名单写在项目配置里，可以为空 |
| 谁能打开 | 本机使用者 | 不支持分享，只有本机使用者 | 本机使用者 |
| 对话谁能看 | 默认私有，可把某一条单独开放 | 只有本机使用者 | 本机使用者看到全部任务 |
| 知识库、连接器 | 选进专家的，按本机资源使用 | 主持人不挂 | 项目默认与对话选择都按本机资源使用 |
| 技能 | 挂在专家上，由本机使用者管理 | 主持人不挂技能 | 和专家一样，挂在项目上 |
| 制品 | 专家工作区 | 各写各的工作区 | 项目工作区 |

联系：

- 项目和专家共用同一套技能、知识库、连接器、工作区和记忆。团队主持人是调度壳，这些能力在成员专家上。
- 单人模式下没有「准入」这一层：专家、团队、项目都只有本机使用者一个归属，不存在点名用户、指定分组或其他登录者。团队仍保持不分享。
- 任务不另建表。专家的会话、团队房间、项目任务都是 `threads`。
- 可调用的专家仍是普通专家。项目调用他们是一次工具返回，不是团队那种上墙派工。

## 谁能用

单人模式下没有「准入」与分组：项目创建后归本机使用者所有，全部任务、追问和待审批都由你处理。名称、可见范围、默认知识库、默认连接器、技能和可调用专家，也都由你修改。

## 知识库和连接器

分成两层。

项目上选中的默认知识库和默认连接器，每次任务都带上，按本机使用者身份调用。资源不需要先共享，也不会按用户再过滤；凭证只在这个项目里生效，对话里不能拿掉这层默认。

发消息时还可以再选，可选范围就是本机已有的资源，加在项目默认之上。

因此一次任务里可以同时有两层：项目默认，加上对话里勾选的。

专家上的知识库和连接器也按本机资源使用，不再按用户可见范围过滤。

## 技能

技能跟专家一样管理：挂在这个项目上，由本机使用者启用或停用。所有对话都用这一份，不再按用户授权。

## 任务

一条任务就是这个项目下的一条对话；本机使用者可以看到全部任务，不必逐条点共享。

状态从这一轮运行情况读出来，不另做工单：

- **进行中**：这一轮还在跑。有人追问后，从已完成回到进行中。
- **待审批**：停在工具确认上，本机使用者可以直接处理。
- **已完成**：这一轮正常结束。
- **失败**：这一轮出错结束。现有接口若还没有失败标记，第一版先不画这个图标。

创建人记在对话上。改名、置顶、删除、分叉，以及模型和审批设置都由本机使用者操作。调用专家产生的内部会话不出现在任务列表里。

记忆是这个项目专家的一份，项目内共用。

## 页面

左侧导航增加「项目」，路径 `/projects`。

列表是卡片：名称、简介、进行中和待审批的数量。本机使用者可以新建、编辑、删除。

详情列出当前绑定，本机使用者可改：

- 知识库
- 连接器
- 技能
- 可调用的专家

页头有「打开任务」，进入聊天里的这个项目。

聊天侧栏的分页为「专家 / 团队 / 项目」。单人模式下这些页签展示的都是本机资源；通过 Bridge 接入的对端专家和对端团队仍分别归在「专家」「团队」里，云端协同页面留在原入口。

「项目」下展开的是任务。进行中和待审批排在前面，可筛「全部 / 进行中 / 待审批」。按钮写「新任务」。每一行有标题、状态、发起人头像，名字在悬停时出现。

任务页仍是现在的聊天。顶栏标「项目」，下面一行只读摘要链到项目详情。制品在右侧文件栏，读这个项目的工作区。

## 实现时沿用的结构

不新建项目表，也不新建任务表。

- `agents.kind` 增加 `project`。现在只接受 `expert` 和 `team`。
- 可调用专家写在该专家配置里的一份 id 列表，不用团队清单。
- 运行时走专家装配，不套主持人的工具白名单。`ask_agent` 用专家现有的同步调用，名单之外的专家调不到；名单为空就不提供这项工具。
- 项目线程对本机使用者全部可见。追问、作者和待审批走已有的会话路径。专家上的逐条共享保持不变。
- 团队不支持分享，`TEAM_NOT_SHAREABLE` 继续只拦团队；单人模式下这一限制不会被用户触发。

## 不做

- 不把项目做成共享团队，不放开团队分享。
- 不做按用户的准入，也不新增成员表；单人模式下所有资源只有本机使用者一个归属。
- 不做看板、项目动态、关闭后锁定的工单。
- 不把项目默认的知识库和连接器复制进本机资源列表。
